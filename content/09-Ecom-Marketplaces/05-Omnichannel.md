# 05 — Омниканальность

> Омниканальность — это **интеграция онлайн- и офлайн-каналов** ради бесшовного опыта покупателя. BOPIS, BORIS, Ship-from-Store, Endless Aisle — операционные режимы, превращающие отдельные каналы в интегрированную экосистему. Зрелая омниканальность — конкурентное преимущество ритейлеров с физическим присутствием против чисто онлайновых игроков.

## Карта раздела

![](attachments/diagrams/09-omnichannel-models.svg)

## 1. Омниканальность против многоканальности

### 1.1 Различие

**Многоканальность:** компания продаёт через несколько каналов независимо:
- Розничные магазины
- Собственный сайт
- Маркетплейсы
- Каталог

Каждый канал отдельный; покупательский опыт несогласованный.

**Омниканальность:** интегрированный опыт по всем каналам:
- Согласованные цены и промо
- Общая видимость запасов
- Кросс-канальное выполнение заказов
- Единый профиль покупателя

Покупатель может начать путь в одном канале, закончить в другом.

### 1.2 Ожидания покупателя

Современный покупатель ожидает:

- Те же цены онлайн и офлайн
- Заказать онлайн, забрать в магазине
- Купить онлайн, вернуть в магазине
- Увидеть товар в магазине, купить в приложении
- Программа лояльности работает везде

Невыполнение — неудовлетворённость и потерянные продажи.

### 1.3 Сложности внедрения

- **Интеграция запасов** — единая картина по всем локациям
- **Согласованность цен** — один и тот же товар по одной цене
- **Управление заказами** — решения по маршрутизации
- **Обработка возвратов** — обработка из любого источника
- **Профиль покупателя** — единая база данных
- **Обучение персонала** — сотрудники магазина нуждаются в цифровых навыках

### 1.4 Бизнес-кейс

Омниканальные покупатели обычно:

- Тратят на 30–40% больше, чем покупатели одного канала
- Имеют более высокую LTV
- Более лояльны
- Сильнее рекомендуют бренд

Но требуются значительные инфраструктурные инвестиции.

**Ключевой вывод 1.** Омниканальность — стратегический императив для ритейлеров с физическим присутствием. Ожидания покупателя заданы; нужен конкурентный паритет. Значительные инвестиции, но высокая отдача.

## 2. BOPIS — Buy Online, Pick-up In Store (купить онлайн, забрать в магазине)

### 2.1 Концепция

![](attachments/diagrams/09-omnichannel-models.svg)

**BOPIS** — покупатель приобретает онлайн, забирает в физическом магазине.

Распространённые синонимы:

- **Click-and-Collect** (термин в Великобритании / Европе)
- **In-Store Pickup**
- **Pickup-in-Store**

### 2.2 Выгоды для покупателя

- **Нет платы за доставку**
- **Быстрее, чем доставка домой** (часто в тот же день)
- **Не нужно быть дома** к доставке
- **Проверить товар** перед получением
- **Простые возвраты** в магазине
- **Добавить покупки** на месте

### 2.3 Выгоды для ритейлера

- **Дополнительный трафик в магазине** (часто покупают сверху)
- **Ниже стоимость выполнения** по сравнению с доставкой домой
- **Снижение возвратов** (можно обменять сразу)
- **Улучшение использования запасов**
- **Конкурентный паритет** с чистыми онлайн-игроками

### 2.4 Операционные требования

#### 2.4.1 Видимость запасов

Система должна показывать наличие в реальном времени при заказе. Ложная недоступность = потерянные продажи; ложная доступность = «кошмар» клиентской поддержки.

#### 2.4.2 Процесс сборки / упаковки

Персонал обучен / выделен для выполнения:
- Заказ получен
- Собран из торгового зала / склада
- Упакован / проверен
- Удерживается для покупателя
- Передан

Типичный SLA: 2 часа готовности (в часы работы магазина), к следующему дню (для ночных заказов).

#### 2.4.3 Уведомления покупателю

- Заказ подтверждён
- Готов к получению
- Напоминание, если не забрали
- Авто-отмена через X дней

#### 2.4.4 Площадь в магазине

Выделенная зона выдачи:
- Видимая / легко найти
- Соответствующий персонал
- Опция curbside (выдача из машины)
- Самообслуживание через ячейки (новая концепция)

### 2.5 Российская реализация

В РФ:

- **WB / Ozon ПВЗ (пункты выдачи заказов)** — доминирующая модель выдачи (но это сеть маркетплейса, а не классический BOPIS)
- **Магазины X5 / Магнит** — развивающиеся программы BOPIS
- **DIY (Леруа Мерлен, OBI)** — сильный BOPIS
- **Fashion** — ограниченное принятие

Сеть ПВЗ — уникальная российская особенность, в некоторой степени замещающая BOPIS.

**Ключевой вывод 2.** BOPIS — зрелое омниканальное предложение. Популярно у покупателей; эффективно для ритейлера. Российский контекст — сеть ПВЗ конкурирует с традиционным BOPIS.

## 3. BORIS — Buy Online, Return In Store (купить онлайн, вернуть в магазине)

### 3.1 Концепция

**BORIS** — покупатель приобретает онлайн, возвращает в физическом магазине.

### 3.2 Почему ценно

- **Проще возвраты** для покупателя (нет упаковки, доставки)
- **Быстрее возврат денег** (сразу в некоторых случаях)
- **Снижение обработки возвратов** для ритейлера
- **Возможность работы с клиентом** (обмен, апсейл)
- **Генерация трафика в магазине**

### 3.3 Операционные соображения

#### 3.3.1 Политика возврата

Ясная, простая:
- Что возвращается
- Временные окна
- Способы возврата средств
- Необходимая документация

#### 3.3.2 Обработка запасов

Возвращённые товары:
- Осматриваются на возможность перепродажи
- Тегируются соответствующим образом
- Восстанавливаются на складе или уцениваются
- Повреждённые идут в clearance / утилизацию

#### 3.3.3 Клиентская поддержка

Персонал обучен:
- Быстро обрабатывать возвраты
- Идентифицировать возможности апсейла
- Разрешать проблемы

### 3.4 Гибридные сценарии

Комбинации:

- Купить онлайн → забрать в магазине → вернуть в магазине, если не подошло
- Купить в магазине → вернуть онлайн (отправить почтой)
- Подписочные продукты → возврат через любой канал

Растущая сложность, растущие ожидания покупателей.

**Ключевой вывод 3.** BORIS снижает «трение» возврата — улучшает удовлетворённость покупателя и повторные покупки. Операционно проще, чем традиционные почтовые возвраты. Интегрировано с потенциалом «повторного вовлечения» в магазине.

## 4. Ship-from-Store (отгрузка из магазина)

### 4.1 Концепция

**Ship-from-Store** — физические магазины служат мини-центрами выполнения заказов, отгружая заказы напрямую.

### 4.2 Почему эффективно

- **Быстрее доставка** (ближе к покупателю)
- **Ниже стоимость доставки** (короче расстояния)
- **Использование запасов** — двигает медленно идущие магазинные запасы
- **Снижение нагрузки на центральный распределительный центр** — распределённая модель

### 4.3 Реализация

Требует:

#### 4.3.1 Умная маршрутизация

Алгоритм решает:
- Какой магазин выполняет заказ?
- На основе доступности запаса, расстояния, мощности магазина
- Оптимизация в реальном времени

#### 4.3.2 Возможности магазина

- Обучение сборке / упаковке
- Доступные упаковочные материалы
- Интеграция забора груза курьерами
- Управление трекингом

#### 4.3.3 Точность запасов

Критично:
- Видимость в реальном времени
- Процессы сверки
- Циклический пересчёт

Неточный запас = разочарование покупателя.

### 4.4 Компромиссы

#### Плюсы:
- Быстрее доставка
- Ниже стоимость
- Распределение нагрузки
- Максимизация запасов

#### Минусы:
- Стоимость труда в магазине (не специализированный)
- Медленнее на заказ, чем в распределительном центре
- Вариативность качества
- Риск отсутствия в торговом зале

### 4.5 Когда работает лучше всего

- Распределённая клиентская база
- Запас распределён по магазинам
- Стандартные продукты (не хрупкие / кастомные)
- Умеренные объёмы
- Доступна ёмкость труда в магазине

**Ключевой вывод 4.** Ship-from-Store — мощная омниканальная способность. Быстрее доставка, ниже стоимость, но операционная сложность. Наиболее эффективно с умными системами маршрутизации.

## 5. Endless Aisle (бесконечная полка)

### 5.1 Концепция

**Endless Aisle** — в магазине покупатель может заказать продукты, **отсутствующие на полке**, из центрального запаса.

### 5.2 Почему полезно

- **Не потерять продажи**, когда товара нет в наличии
- **Меньшие магазины** могут предлагать широкий выбор
- **Тестирование новых продуктов** без полного развёртывания
- **Премиальные / нишевые товары** с ограниченным спросом

### 5.3 Реализация

Обычно через:

- **Планшет / киоск** в магазине
- **Устройство сотрудника** (мобильное / планшет)
- **Собственное приложение покупателя**, сканирующее QR-код

Заказ оформлен; доставлен покупателю домой или в магазин (для следующего визита).

### 5.4 Пример Apple Store

Apple Store — классическая реализация:

- Небольшая площадь, ограниченный запас
- Сотрудники с iPad — полный доступ к каталогу
- Заказ оформляется в магазине, отгрузка домой
- Или получение позже, если покупатель предпочитает

### 5.5 Ограничения

- Разочарование, если покупатель хотел унести с собой
- Нужен интегрированный технический стек
- Обучение сотрудников
- Образование покупателей

**Ключевой вывод 5.** Endless Aisle расширяет возможности физического магазина за пределы полки. Особенно ценно для небольших магазинов или специализированных / премиум-продуктов. Требуются инвестиции в технологии и обучение.

## 6. OMS — Order Management System (система управления заказами)

### 6.1 Что такое OMS

**OMS** — основа интеграции всех омниканальных операций. Центральная система для:

- Приёма заказов (со всех каналов)
- Проверки запасов (в реальном времени по всем локациям)
- Решений маршрутизации (где выполнить?)
- Координации выполнения
- Исполнения отгрузки
- Коммуникации с покупателем
- Обработки возвратов

### 6.2 Ключевые возможности

#### 6.2.1 Многоканальный приём заказов

Агрегация заказов из:
- Собственного сайта
- Маркетплейсов (WB, Ozon и др.)
- B2B-портала
- Телефона / EDI (Electronic Data Interchange — электронный обмен данными)
- В магазине

#### 6.2.2 Запас в реальном времени

Видимость по:
- Распределительным центрам
- Розничным магазинам
- В пути
- На удержании / зарезервированному

#### 6.2.3 Умная маршрутизация

Решить, кто выполняет:
- Оптимизация стоимости
- Оптимизация скорости
- Стратегический баланс (например, сначала движение медленно идущих запасов)
- Предпочтение покупателя

#### 6.2.4 Клиентская поддержка

Единый взгляд на покупателя:
- Все заказы по всем каналам
- Возвраты / возмещения
- Жалобы / запросы
- Статус лояльности

#### 6.2.5 Отчётность / аналитика

Кросс-канальная производительность:
- Продажи по каналам
- Стоимость выполнения
- Поведение покупателей
- Производительность запаса

### 6.3 Поставщики OMS

Глобальные:

- **IBM Sterling**
- **Manhattan Associates**
- **Aptos**
- **Shopify Plus** (встроенный, для меньших)
- **Salesforce Commerce Cloud**

Российские / региональные:

- **Bitrix24** (более широкий, включает OMS)
- **1C: Управление торговлей**
- Кастомные интеграции

### 6.4 Сложность внедрения

OMS — изощрённое ПО, требует:

- Значительной конфигурации
- Интеграции с ERP / WMS (Warehouse Management System — система управления складом) / e-commerce-платформами
- Миграции / очистки данных
- Обучения персонала
- Управления изменениями

Типичное внедрение 6–18 месяцев для полной омниканальности.

**Ключевой вывод 6.** OMS — основа, делающая омниканальность возможной. Без интегрированного OMS истинная омниканальность невозможна. Значительные инвестиции, но энэйблер для всех остальных способностей.

## 7. Аспекты клиентского опыта

### 7.1 Единая лояльность

Единая программа по всем каналам:

- Начисление / списание баллов везде
- Видимый везде статус
- Персонализированные предложения (на основе кросс-канального поведения)

### 7.2 Персонализация

Кросс-канальные данные позволяют:

- Email на основе поведения в магазине
- Веб-рекомендации на основе магазинных покупок
- Таргетированную рекламу на основе истории просмотров
- Кастомизированные опыты

Соображения приватности: 152-ФЗ, GDPR в применимых контекстах.

### 7.3 Согласованный брендинг

Один и тот же вид / ощущение / сообщения по каналам:

- Визуальная айдентика
- Тон голоса
- Подход к клиентской поддержке
- Стандарты качества

Несогласованность подрывает доверие к бренду.

### 7.4 Mobile-first

Покупательский путь часто мобильный:

- Поиск по телефону (исследование)
- Сравнение по телефону (в магазине)
- Покупка с телефона (в любое время)
- Отслеживание доставки с телефона

Приложения + мобильно-оптимизированный веб — необходимы.

**Ключевой вывод 7.** Интеграция клиентского опыта — конечная цель омниканальности. Единая лояльность, персонализация, согласованный брендинг, mobile-first дизайн — все компоненты.

## 8. Российская омниканальность

### 8.1 Ландшафт

В РФ:

- **Маркетплейсы доминируют онлайн** — отличается от США / Европы
- **Сеть ПВЗ** — уникальное ожидание покупателя
- **Ожидание более быстрой доставки** (доставка в тот же день обычна в больших городах)
- **Наложенный платёж** всё ещё значимый
- **Распространение программ лояльности**

### 8.2 Ведущие ритейлеры

#### X5 (Перекрёсток / Пятёрочка)

- Интеграция нескольких форматов
- Онлайн (Перекрёсток Vprok)
- Pickup
- Подписка
- Программа лояльности

#### Магнит

- Платформа Магнит Онлайн
- Сеть выдачи
- Magnit Pay
- Программы лояльности

#### Лента / Ашан

- Онлайн + pickup
- B2B-платформы (Ашан Business)

#### Wildberries / Ozon

- Преимущественно онлайн, но добавляют BOPIS-подобное через ПВЗ

### 8.3 Сложности

- Унаследованные IT-системы
- Географический масштаб
- Различная региональная динамика
- Давление по стоимости
- Дефицит навыков в омниканальной экспертизе

### 8.4 Будущая траектория

Растущие инвестиции в:

- Персонализацию на основе AI
- Голосовую коммерцию
- Live commerce (живая коммерция)
- Интеграцию социальной коммерции
- AR / VR-опыты

Крупные ритейлеры активно строят омниканальные возможности.

**Ключевой вывод 8.** Российский омниканальный ландшафт — уникальные характеристики. ПВЗ замещает часть BOPIS; маркетплейсы доминируют онлайн. Ведущие ритейлеры тяжело инвестируют; конкуренция усиливается.

## Сводный практический протокол

Оценка зрелости омниканальности:

| Уровень | Возможности |
|---------|-------------|
| 1 — Базовый | Несколько каналов, отдельные операции |
| 2 — Интегрированный запас | Видимость в реальном времени |
| 3 — BOPIS / BORIS | Базовые омниканальные предложения |
| 4 — Ship-from-Store | Распределённое выполнение |
| 5 — Полная омниканальность | OMS + персонализация + аналитика |
