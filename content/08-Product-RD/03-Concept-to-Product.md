# 03 — От концепции к продукту

> Превращение инсайтов в конкретный продукт — самая техническая часть управления продуктом. Design Thinking даёт рамку идеации и итерации; PRD формализует спецификации; концепт-тестирование валидирует; DFMA / DFSS делает продукт пригодным для производства. Это **мост между покупательскими инсайтами и массовым производством**.

## Карта раздела

![](attachments/diagrams/08-design-thinking-process.svg)

## 1. Design Thinking (дизайн-мышление)

### 1.1 Контекст и легитимность

**Design Thinking** — методология решения проблем через дизайнерский подход, разработанная **IDEO** и **Stanford d.school**. Канонические книги:

- Tim Brown, **«Change by Design»** (2009) — CEO IDEO
- Stanford d.school, **«Design Thinking Bootcamp Bootleg»** — бесплатное руководство

Используется P&G, IBM, GE, Apple (эпоха Jonathan Ive), Airbnb.

### 1.2 Пять стадий

![](attachments/diagrams/08-design-thinking-process.svg)

#### Стадия 1 — Empathize (эмпатия)

Глубокое понимание пользователя. Методы:

- **Observation (наблюдение)** — наблюдать за пользователями в естественном контексте
- **Interviews (интервью)** — открытые разговоры
- **Immersion (погружение)** — пережить ситуацию покупателя
- **Empathy mapping (карта эмпатии)** — визуализация покупательского опыта

Результат: глубокое понимание потребностей, болей, устремлений пользователя.

#### Стадия 2 — Define (определение)

Синтез изученного в действенную формулировку проблемы.

**POV (Point of View — точка зрения)** в формате:
- «Пользователь: [тип пользователя]»
- «Нуждается в: [конкретная потребность]»
- «Потому что: [инсайт]»

**HMW (How Might We — как мы могли бы)** — переформулировка:
- «Как мы могли бы [направление решения] для [пользователя], чтобы [результат]?»

Пример: «Как мы могли бы переделать спортивные наушники для бегунов, которые сильно потеют, чтобы они не выскальзывали?»

#### Стадия 3 — Ideate (генерация идей)

Породить множество решений. Методы:

- **Brainstorming (мозговой штурм)** — сначала количество, потом качество
- **Crazy 8s** — 8 идей за 8 минут
- **SCAMPER** — систематические креативные подсказки (Substitute / заменить, Combine / объединить, Adapt / адаптировать, Modify / модифицировать, Put to other use / использовать иначе, Eliminate / устранить, Reverse / развернуть)
- **Worst possible idea (худшая возможная идея)** — парадоксальная инверсия
- **Storyboarding (раскадровка)** — визуальные истории

Результат: множество расходящихся идей для последующей сходимости.

#### Стадия 4 — Prototype (прототипирование)

Создать материальные версии. Спектр:

- **Бумажные прототипы** — наброски, макеты
- **Раскадровки** — визуальные последовательности
- **Ролевые игры** — проигрывание сценариев
- **Модели из пены / картона** — физические 3D
- **3D-печатные прототипы** — ближе к реальному
- **Функциональные прототипы** — рабочие версии

Принцип: **«падать быстро, падать дёшево»** (Fail fast, fail cheap). Не доводите прототип до совершенства — учитесь на нём.

#### Стадия 5 — Test (тестирование)

Валидация с реальными пользователями. Методы:

- **User testing (тестирование пользователями)** — наблюдение за взаимодействиями
- **A/B-тестирование** — сравнение альтернатив
- **Опрос** — количественная обратная связь
- **Фокус-группы** — обсуждения
- **Пилотные программы** — длительное использование

Критично: **тестируйте для извлечения уроков, а не для подтверждения**. Опровергающая обратная связь — самая ценная.

### 1.3 Итеративные циклы

Design Thinking — **итеративный**, а не линейный. Распространённые шаблоны:

- Тест → возврат к Ideate (нужно больше решений)
- Тест → возврат к Define (проблема понята недостаточно)
- Prototype → возврат к Ideate (идея не работает)
- Empathize → дополнительное вовлечение (нужны новые данные)

Множественные циклы типичны для крупных инноваций.

### 1.4 Применение для физических товаров

В контексте FMCG / товаров:

- Empathize: наблюдение за шоперами, этнография в магазинах / дома
- Define: задачи упаковки / рецептуры / опыта
- Ideate: рецептуры, дизайны упаковки, маркетинговые концепции
- Prototype: лабораторные образцы, макеты, тестовая упаковка
- Test: тесты использования дома, концепт-тесты, сенсорная оценка

P&G активно использует Design Thinking.

**Ключевой вывод 1.** Design Thinking — универсальная рамка для инноваций. Итеративный, клиентоориентированный, прототипо-управляемый. Работает в разных отраслях, устоялся в FMCG-разработке.

## 2. PRD — Product Requirements Document (документ требований к продукту)

### 2.1 Что это

**PRD** — формальная спецификация продукта для команды разработки.

Функция:

- **Единый источник истины** для продукта
- **Инструмент коммуникации** между PM, инженерией, маркетингом, прочими
- **Запись решений** по сделанному выбору
- **Опора** для тестирования и контроля качества (QA — Quality Assurance)

Без хорошего PRD разработка превращается в хаос.

### 2.2 Структура PRD

Стандартные разделы:

#### 2.2.1 Background (контекст)

- Потребность покупателя / JTBD
- Рыночная возможность
- Стратегическое обоснование

#### 2.2.2 Target Customer (целевой покупатель)

- Основная аудитория
- Сценарии использования
- Персоны (если применимо)

#### 2.2.3 Product Description (описание продукта)

- Обзор концепции
- Характеристики (спецификации)
- Форма, функция, ингредиенты
- Спецификации производительности

#### 2.2.4 Functional Requirements (функциональные требования)

- Что продукт должен делать
- Критерии производительности
- Совместимость / взаимодействие

#### 2.2.5 Non-Functional Requirements (нефункциональные требования)

- Стандарты качества
- Цели по надёжности
- Соответствие регулированию

#### 2.2.6 Constraints (ограничения)

- Целевая себестоимость (target costing)
- Время вывода на рынок
- Лимиты ресурсов
- Регуляторные

#### 2.2.7 Success Criteria (критерии успеха)

- KPI для измерения успеха
- Критерии приёмки
- Критерии запуска

### 2.3 Дисциплина PRD

Лучшие практики:

- **«Живой» документ** — обновляется по мере принятия решений
- **Версионирование** — отслеживание изменений
- **Согласован** — кросс-функциональная подпись
- **Конкретный** — измеримый, проверяемый
- **Сжатый** — достаточно деталей, но без бюрократии

### 2.4 Российская практика

В РФ PRD часто:

- Менее формализован, чем в международных корпорациях
- Заменяется простыми «техническими заданиями» (ТЗ)
- Часто объединён с маркетинговым брифом
- Качество сильно варьируется в зависимости от зрелости компании

Зрелые компании (Сбер, X5, Wildberries) используют полную дисциплину PRD.

**Ключевой вывод 2.** PRD — основа формальной разработки продукта. Качественный PRD предотвращает более 50% проблем разработки. Инвестиция в правильную дисциплину PRD окупается многократно.

## 3. Концепт-тестирование

### 3.1 Зачем

Перед инвестированием в серьёзную разработку — протестируйте концепцию с потенциальными покупателями. Уловить проблемы рано, когда изменения дешевы.

### 3.2 Методы концепт-тестирования

#### 3.2.1 Монадический тест

Одна концепция, реакции собираются. Плюс: глубокий фокус. Минус: нет сравнения.

#### 3.2.2 Сравнительное тестирование

Несколько концепций параллельно. Плюс: сравнительные инсайты. Минус: эффекты порядка.

#### 3.2.3 Последовательно-монадический

Несколько концепций, но по одной за раз. Плюс: глубокий разбор каждой плюс сравнение. Минус: дольше.

### 3.3 Форматы презентации концепции

- **Словесное описание** — ранняя стадия
- **Эскизы / иллюстрации** — раннее визуальное
- **3D-рендеры** — уточнённое визуальное
- **Физические прототипы** — самое реалистичное

### 3.4 Метрики концепт-тестирования

Стандартные метрики:

- **Намерение купить** («точно куплю / вероятно куплю / возможно / вероятно нет / точно нет»)
- **Уникальность** («ново для меня / похоже на существующее»)
- **Доверие к утверждениям** («верю / не верю заявлениям»)
- **Потребность** («закрывает реальную потребность / нет потребности»)
- **Ценность** («справедливая цена / слишком дорого»)

Отраслевые ориентиры:

- Концепции верхней квартили: 60%+ «точно + вероятно куплю»
- Медианные концепции: 35–45%
- Нижняя квартиль: < 25%

### 3.5 Conjoint Analysis (совместный анализ)

Изощрённая техника для понимания компромиссов:

- Покупателям показывают комплекты атрибутов и цен
- Алгоритм извлекает веса предпочтений
- Раскрывает «что они на самом деле хотят»

Используется при множественных характеристиках / ценовых сценариях.

Инструменты: Sawtooth Software, Lighthouse Studio.

### 3.6 BASES — прогноз предстартовых продаж

**BASES** (Nielsen) — закрытый инструмент прогнозирования продаж при запуске на основе концепт-тестов. Используется P&G, Coca-Cola, Unilever и многими FMCG.

Комбинирует:
- Оценки концепт-тестирования
- Предположения по дистрибуции
- Цены
- Маркетинговые инвестиции

Результат: прогнозируемый объём / доля при запуске.

**Ключевой вывод 3.** Концепт-тестирование — необходимый шаг валидации. Дешёвая защита от дорогих провалов. В сочетании с инструментами вроде BASES радикально повышает долю успешных запусков.

## 4. DFMA — Design for Manufacture and Assembly (проектирование под производство и сборку)

### 4.1 Концепция

**DFMA** — инженерная дисциплина создания продуктов, **простых и дешёвых в производстве**.

Разработана Boothroyd Dewhurst в 1980-х годах. Используется во всей отрасли.

### 4.2 Принципы DFMA

#### 4.2.1 Минимизировать количество деталей

Меньше деталей = ниже себестоимость, меньше точек отказа, быстрее сборка.

Методы:
- **Функциональная консолидация** — много функций в одной детали
- **Устранение материалов** — только необходимое
- **Стандартные детали** — стандарт вместо кастомных

#### 4.2.2 Стандартизировать детали

- Общие компоненты для разных продуктов
- Стандартный крепёж по отраслевым нормам
- Модульный дизайн

#### 4.2.3 Проектировать под сборку

- Сборка сверху-вниз предпочтительнее
- Самопозиционирующиеся детали
- Защита от ошибок ориентации (только один способ собрать)
- Минимум перехватов рук

#### 4.2.4 Производственно-дружественный дизайн

- Избегать острых внутренних углов (трудно фрезеровать)
- Допускать конусность (для литья)
- Стандартные допуски (узкие допуски дороги)
- Учёт выбора материалов

### 4.3 Эффект DFMA

Заявленные выгоды:

- Снижение количества деталей на 40–60%
- Снижение времени сборки на 30–50%
- Снижение общей себестоимости на 20–40%
- Улучшение качества (меньше ошибок сборки)

### 4.4 Кросс-функциональные команды

DFMA требует сотрудничества инженерии + производства + дизайна. Старая модель «перебросить через стену» проваливается. Современные интегрированные продуктовые команды.

**Ключевой вывод 4.** DFMA — критичен для экономики производства. Инженерные решения, принятые рано, фиксируют издержки навсегда. Инвестиции в обучение и инструменты DFMA — высокая окупаемость.

## 5. DFSS — Design for Six Sigma (проектирование под Шесть сигм)

### 5.1 Концепция

**DFSS** — расширение дисциплины качества Шесть сигм на этап дизайна продукта.

Логика: дешевле спроектировать качество, чем потом инспектировать.

### 5.2 DMAIC против DMADV

- **DMAIC** (Define, Measure, Analyze, Improve, Control — определить, измерить, проанализировать, улучшить, контролировать) — классические Шесть сигм для существующих процессов
- **DMADV** (Define, Measure, Analyze, Design, Verify — определить, измерить, проанализировать, спроектировать, верифицировать) — фреймворк DFSS для новых продуктов

### 5.3 Этапы DMADV

#### Define (определение)

Цели проекта; потребности покупателя (CTQ — Critical to Quality — критические для качества).

#### Measure (измерение)

Количественные значения CTQ; ориентиры; метрики.

#### Analyze (анализ)

Определение вариантов дизайна; анализ компромиссов.

#### Design (проектирование)

Детальный дизайн; оптимизация; прогнозное моделирование.

#### Verify (верификация)

Пилотный тест; валидация работоспособности; передача в эксплуатацию.

### 5.4 Инструменты и техники

- **QFD** (Quality Function Deployment — развёртывание функции качества) — перевод потребностей покупателя в инженерные спецификации
- **Анализ допусков** — распространение отклонений
- **DOE** (Design of Experiments — планирование экспериментов) — эффективное экспериментирование
- **FMEA** (Failure Mode and Effects Analysis — анализ видов и последствий отказов) — превентивный анализ рисков
- **Робастный дизайн** (методы Тагути) — нечувствительный к отклонениям

### 5.5 Отраслевое применение

DFSS широко используется в:

- Автомобилестроении (Ford, GM)
- Авиастроении (Boeing)
- Медицинском оборудовании
- Электронике
- Фармацевтике

Реже в FMCG, но получает распространение.

**Ключевой вывод 5.** DFSS встраивает дисциплину качества в дизайн. Высокие первоначальные инвестиции, но радикальное снижение постзапусковых проблем. Критично для регулируемых отраслей, ценно для всех.

## 6. Прототипирование в товарах

### 6.1 Типы прототипов

Разные уровни проработки:

- **Концептуальный прототип** — доказывает идею (грубый, быстрый)
- **Инженерный прототип** — валидирует инженерные решения (функциональный)
- **Производственный прототип** — представляет производственную версию
- **Пилотное производство** — предзапусковый объём

### 6.2 Инструменты для физических прототипов

- **3D-печать** — радикальное снижение стоимости / времени прототипирования
- **ЧПУ-обработка** — высокоточные кастомные детали
- **Литьё в песок** — быстрые металлические детали
- **Вакуумное формование** — прототипы упаковки
- **Ручные модели** — ранние концепции

### 6.3 Итерационные циклы

Современное прототипирование позволяет быструю итерацию:

- 3D-печатные детали за часы (вместо недель для кастомной оснастки)
- Несколько вариантов тестируются одновременно
- Обратная связь от покупателей, пока прототипы ещё гибкие

Это значительно сжимает традиционные сроки разработки нового продукта.

### 6.4 Специфика FMCG

Для FMCG-прототипов:

- **Рецептуры** — лабораторные версии разрабатываются итеративно
- **Сенсорное тестирование** — оценка вкуса, запаха, ощущений
- **Макеты упаковки** — визуальные / структурные тесты
- **Тестирование выкладки** — внешний вид на полке
- **Опытные производственные партии** — пилотное производство

**Ключевой вывод 6.** Современное прототипирование в 10 раз быстрее / дешевле, чем 20 лет назад. Позволяет мышление «проектирования через эксперимент». Компании, использующие современное прототипирование, существенно опережают конкурентов в традиционных циклах.

## Сводный практический протокол

Цикл от концепции к продукту для нового физического продукта за 9 месяцев:

| Период | Активности |
|--------|-----------|
| Месяцы 1–2 | Discovery (Stage-Gate этапы 1–2); черновик PRD |
| Месяцы 3–4 | Сессии Design Thinking; первые прототипы |
| Месяц 5 | Концепт-тестирование; уточнение |
| Месяцы 6–7 | Инженерия (DFMA, DFSS); производственный прототип |
| Месяц 8 | Предпроизводственное тестирование; валидация |
| Месяц 9 | Пилотное производство; предзапусковая подготовка |

## Применение для руководителя

| Целевая роль | Что взять из заметки |
|--------------|---------------------|
| **CPO / директор по продукту** | Стратегические решения по методологии дизайна; инвестиции в инструменты и обучение |
| **R&D-директор** | Дисциплина DFMA / DFSS; продуктивность инженерии |
| **Продакт-менеджер** | Дисциплина PRD; лидерство в концепт-тестировании |
| **Дизайнер / UX-специалист** | Фасилитация Design Thinking; создание прототипов |
| **COO** | Производственно-дружественный дизайн; оптимизация себестоимости через DFMA |
