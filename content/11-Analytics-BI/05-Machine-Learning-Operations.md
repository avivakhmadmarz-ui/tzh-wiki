# 05 — Машинное обучение для операций

> ML (Machine Learning — машинное обучение) превратилось из R&D-направления в операционную необходимость: прогноз спроса, оптимизация запасов, сегментация клиентов, обнаружение аномалий, LLM (Large Language Models — большие языковые модели) в работе с документами. Этот раздел — про **главные применения ML в операциях**, понимание ROI каждого применения и разумные ожидания от внедрения.

## 1. Что такое ML и когда оно работает

### 1.1 Контекст и легитимность

Современное ML оформилось в 2010-х после прорыва глубокого обучения (deep learning). Каноничные книги — **Aurélien Géron, «Hands-On Machine Learning with Scikit-Learn, Keras, TensorFlow»** (O'Reilly, 3-е изд. 2022) — для практиков; **Christopher Bishop, «Pattern Recognition and Machine Learning»** (Springer, 2006) — академический стандарт.

LLM-революция (ChatGPT, GPT-4, Claude) с 2022 года добавила новый уровень: модели общего назначения для текста, кода, изображений.

### 1.2 Когда ML даёт ценность

ML работает, когда есть:

1. **Большое количество данных** — минимум тысячи, лучше десятки тысяч примеров
2. **Закономерности в данных** — есть что предсказывать
3. **Стабильность задачи** — поведение не меняется радикально каждый месяц
4. **Бизнес-задача** — есть конкретное решение, которое улучшается
5. **Инфраструктура** — данные доступны, есть платформа для деплоя

Без этих условий ML — впустую потраченные ресурсы. Большинство «давайте применим AI» проектов проваливаются именно из-за их отсутствия.

### 1.3 ML vs классическая статистика

| Аспект | Классическая статистика | ML |
|--------|-------------------------|-----|
| **Цель** | Объяснение, причинность | Предсказание |
| **Модели** | Линейная регрессия, GLM | Деревья, ансамбли, нейросети |
| **Интерпретируемость** | Высокая | Часто низкая (black box) |
| **Объём данных** | Может работать на сотнях | Лучше на тысячах+ |
| **Гипотезы** | Pre-registered | Открытый поиск паттернов |

Грань размывается, но фундаментально: статистика отвечает «почему», ML — «что будет дальше».

**Ключевой вывод 1.** ML — мощный инструмент при правильных условиях. Не панацея. Главный вопрос перед внедрением — «есть ли у нас данные и задача, где ML реально нужен?»

## 2. Главные применения ML в операциях

### 2.1 Шесть категорий применений

![](attachments/diagrams/11-ml-use-cases.svg)

В корпоративных операциях ML применяется в 6 основных категориях:

1. **Demand Forecasting** (прогноз спроса)
2. **Customer Segmentation** (сегментация клиентов)
3. **Predictive Maintenance** (предсказательное обслуживание)
4. **Anomaly Detection** (обнаружение аномалий)
5. **Recommender Systems** (рекомендательные системы)
6. **LLM / GenAI** (обработка текста, копайлоты)

### 2.2 Demand Forecasting

**Задача:** спрогнозировать спрос на SKU / категорию / клиента на следующие N периодов.

**Методы (от простого к сложному):**

- **Statistical** — ARIMA, Holt-Winters, ETS. Работают для регулярных рядов, plug-and-play
- **Tree-based** — XGBoost, LightGBM. Лучше при наличии признаков (промо, погода, события)
- **Neural** — LSTM, Transformer (Temporal Fusion Transformer, N-BEATS). Лучше при долгих рядах с нелинейной структурой
- **Specialized** — Prophet (Facebook) — упрощённый интерфейс, готов «из коробки»; DeepAR (Amazon)

**ROI:** улучшение точности прогноза на 5-15% обычно даёт 10-30% снижение запасов при том же уровне сервиса (см. модуль 04 — Inventory Management).

**Главные ошибки:**
- ML без проверки против простых baselines (Naive forecast, moving average)
- Игнорирование external features (промо, события, погода)
- Прогноз без quantification неопределённости (нужны prediction intervals)

### 2.3 Customer Segmentation

**Задача:** разделить клиентов на однородные группы для дифференцированного управления.

**Методы:**

- **RFM-сегментация** (Recency-Frequency-Monetary — давность-частота-денежный объём) — простой rule-based подход
- **K-Means** — кластеризация по континуальным метрикам
- **DBSCAN** — кластеризация с обнаружением выбросов
- **Hierarchical clustering** — иерархическая структура сегментов
- **Gaussian Mixture Models** — вероятностная кластеризация

**ROI:** дифференцированный маркетинг + retention-программы по сегментам обычно дают 10-25% рост LTV vs «один маркетинг для всех».

**Главные ошибки:**
- Сегментация ради сегментации (без последующей дифференциации)
- Слишком много сегментов (≥ 10) — невозможно поддерживать
- Сегментация по легко наблюдаемым, но не релевантным признакам

### 2.4 Predictive Maintenance

**Задача:** предсказать, когда сломается оборудование, чтобы провести обслуживание **до** сбоя.

**Методы:**

- Survival analysis (анализ выживаемости)
- Time-to-failure модели
- Anomaly detection на сенсорных данных
- Reliability engineering методы

**ROI:** сокращение downtime в 2-5 раз, экономия на замене запчастей. Особенно ценно в производстве, логистике, ИТ-инфраструктуре.

**Когда работает:** наличие сенсоров (IoT), исторических данных о поломках, регулярного обслуживания.

### 2.5 Anomaly Detection

**Задача:** обнаружить аномалии — необычные транзакции, отклонения в продажах, сбои в данных.

**Методы:**

- **Statistical** — Z-score, IQR-method (Interquartile Range)
- **Isolation Forest** — изоляция аномалий через случайные деревья
- **Autoencoder** — нейросеть, обучаемая восстанавливать «нормальные» данные
- **One-Class SVM** — классификация на «норма» vs «аномалия»

**Применения:**

- **Антифрод** — необычные транзакции
- **Сбои в данных** — выбросы в ETL
- **Аномалии в продажах** — резкий рост / падение в категории
- **Безопасность** — необычное поведение пользователей

**ROI:** прямая экономия от предотвращённого фрода / простоя.

### 2.6 Recommender Systems

**Задача:** рекомендовать товары / контент / услуги клиенту на основе истории покупок или поведения.

**Методы:**

- **Collaborative filtering** — «клиенты, похожие на тебя, покупали X»
- **Content-based** — «продукты, похожие на те, что ты покупал»
- **Hybrid** — комбинация
- **Deep learning** (Two-Tower, BERT4Rec) — современные методы

**ROI:** Amazon — 35% выручки от рекомендаций; Netflix — 75% просмотров через recommend engine.

**Применения в e-commerce:**

- Cross-sell на product page
- Email-маркетинг с персональными подборками
- Сезонные / периодические покупки (replenishment)
- Upsell в корзине

### 2.7 LLM / GenAI

**Задача:** обработка текста, генерация контента, копайлоты.

**Главные модели 2024-2025:**

- **GPT-4 / GPT-4o** (OpenAI) — флагман по качеству
- **Claude 3.5 / 4 Sonnet / Opus** (Anthropic) — лучше для длинного контекста, безопасности
- **Gemini** (Google) — мультимодальные задачи
- **Llama 3 / 4** (Meta) — open-source альтернатива
- **Российские:** GigaChat (Сбер), YandexGPT

**Применения в операциях:**

- **Document processing** — извлечение данных из договоров, счетов, документов
- **Customer support** — чат-боты первой линии
- **Code copilots** — GitHub Copilot, Cursor для разработки
- **Search & summarization** — корпоративный поиск с резюме
- **Translation** — мгновенный перевод документов
- **Email drafting** — копайлоты в Outlook / Gmail
- **Meeting summaries** — резюмирование звонков

**ROI:** разные оценки, в среднем 20-40% продуктивности в задачах, где LLM применим. Главный риск — галлюцинации (LLM придумывает факты).

**Ключевой вывод 2.** ML в операциях — не «давайте всё прогнозировать», а **выбор 1-2 областей с явным ROI и достаточными данными**. Большинство компаний начинают с demand forecasting или recommender systems как с самой проверенной отдачей.

## 3. Как внедрять ML — практический процесс

### 3.1 Жизненный цикл ML-проекта

```
1. Бизнес-задача → 2. Данные → 3. Baseline → 4. ML-модель →
5. Валидация → 6. Деплой → 7. Мониторинг → 8. Retraining
```

### 3.2 Этапы

**1. Бизнес-задача.** Конкретное решение, которое улучшается ML. Не «давайте применим AI», а «снизить ошибку прогноза с 25% до 15% MAPE для уменьшения запасов на 20%».

**2. Данные.** Доступность, качество, объём. Часто 80% времени проекта — на data engineering. Без чистых данных ML невозможен.

**3. Baseline.** Простейшее решение для сравнения. Naive forecast (прошлый период = прогноз), правило «купить как в прошлом году», просто median по группе.

**4. ML-модель.** От простой (linear regression, decision tree) к сложной (XGBoost, neural). Не начинать с deep learning — это финал, не старт.

**5. Валидация.** Cross-validation, holdout set, статистическая значимость улучшения над baseline.

**6. Деплой.** Production-инфраструктура: API, batch jobs, integration с ERP / CRM. Часто сложнее, чем сама модель.

**7. Мониторинг.** Drift detection (изменение распределения данных), monitoring quality, alerts при деградации.

**8. Retraining.** Регулярное обновление модели на свежих данных. Раз в месяц / квартал / по триггеру.

### 3.3 MLOps — операционализация ML

**MLOps** (Machine Learning Operations) — аналог DevOps для ML:

- **Feature Store** — централизованное хранилище признаков
- **Model Registry** — версионирование моделей
- **CI/CD** для моделей
- **A/B-тесты моделей** — сравнение версий
- **Monitoring** — производительность, drift, fairness

Стандарт для зрелых ML-команд. Инструменты: MLflow, Kubeflow, Sagemaker, Vertex AI.

### 3.4 Главные причины провала ML-проектов

- **Нет бизнес-задачи** — «давайте применим ML»
- **Плохие данные** — недостаточно, грязные, нерелевантные
- **Нет baseline** — ML без сравнения с простым решением
- **Игнорирование деплоя** — модель не выходит из Jupyter notebook
- **Нет мониторинга** — модель деградирует, никто не знает
- **Игнорирование change management** — пользователи не доверяют, не используют

Исследования (Gartner, McKinsey): 70-85% корпоративных ML-проектов не выходят в production.

**Ключевой вывод 3.** ML-проект — это **80% инженерии и change management, 20% моделирования**. Большинство компаний фокусируются на 20% и проваливают 80%.

## 4. Build vs Buy в ML

### 4.1 Три уровня внедрения

| Уровень | Что это | Когда выбирать |
|---------|---------|----------------|
| **Buy SaaS** | Готовое решение (Forecast NOW, Amazon Forecast) | Стандартная задача, нет ML-команды |
| **Customize** | API / open-source с настройкой (Prophet, XGBoost) | Стандартная задача + минимальный ML-навык |
| **Build custom** | Своя ML-команда, кастомные модели | Уникальная задача, ML — конкурентное преимущество |

### 4.2 Когда build

- ML — стратегическое преимущество (рекомендации в e-commerce, прогноз в логистике)
- Уникальные данные / задача
- Долгосрочная инвестиция в data competency

### 4.3 Когда buy

- Стандартная задача (demand forecasting для FMCG)
- Нет внутренней команды
- Быстрый time-to-value важнее

### 4.4 Гибридный подход

Большинство зрелых компаний:
- Buy для стандартных задач (прогноз, антифрод от вендоров)
- Build для core competencies (рекомендации, ценообразование)

**Ключевой вывод 4.** Build vs Buy — стратегическое решение. Build даёт преимущество, но требует огромных инвестиций в команду и платформу. Buy быстрее, но не создаёт конкурентного преимущества.

## 5. LLM в корпоративной практике

### 5.1 Контекст 2024-2025

LLM из «дорогой игрушки» 2022 года превратились в **корпоративный стандарт** к 2025-му:

- ChatGPT Enterprise / Microsoft Copilot развёрнуты в большинстве Fortune 500
- Корпоративные ассистенты на базе LLM в банках, ритейле, медицине
- Российские GigaChat, YandexGPT интегрированы в корпоративные системы

### 5.2 Главные применения

**Productivity copilots:**
- GitHub Copilot — разработка кода (20-40% продуктивности)
- Microsoft 365 Copilot — Word, Excel, PowerPoint, Outlook
- Notion AI — копирайтинг и резюмирование
- Cursor / Windsurf — продвинутая разработка

**Customer-facing:**
- Чат-боты первой линии поддержки
- Поиск по корпоративным документам (RAG — Retrieval-Augmented Generation — генерация с дополненным извлечением)
- Автоматический ответ на email / запросы

**Internal tools:**
- Резюмирование длинных документов (договоры, отчёты)
- Извлечение структурированных данных из неструктурированных (PDF → JSON)
- Анализ настроений в отзывах
- Перевод документации

### 5.3 RAG — Retrieval-Augmented Generation

Главный паттерн внедрения LLM в корпоративный контекст — **RAG**:

1. Корпоративные документы индексируются в **vector database** (Pinecone, Weaviate, ChromaDB)
2. По запросу пользователя ищутся релевантные документы
3. LLM генерирует ответ **на основе извлечённых документов**, не «из памяти»

Это решает проблему галлюцинаций и устаревания знаний LLM.

### 5.4 Главные риски LLM

- **Галлюцинации** — модель уверенно даёт неверную информацию
- **Privacy** — данные могут утечь через промпт в облачную модель
- **Безопасность** — prompt injection (внедрение вредоносных инструкций)
- **Зависимость** — пользователи перестают думать сами
- **Cost** — высокие расходы на API при массовом использовании

### 5.5 Self-hosted LLM

Для приватных задач — локальные модели:

- **Llama 3 / 4** (Meta) — open-source, можно запускать на собственных серверах
- **Mistral** — европейские модели
- **Qwen** (Alibaba) — китайские модели
- **Gemma** (Google) — лёгкие open-source модели

Для запуска нужны GPU (RTX 4090 для 7B-моделей; A100/H100 для 70B+).

**Ключевой вывод 5.** LLM — самая быстро меняющаяся область ML. То, что 2 года назад было R&D, сегодня — корпоративный стандарт. Каждый руководитель должен понимать базовые применения и иметь стратегию.

## Сводный практический протокол

Внедрение первого ML-применения в компании:

| Месяц | Этап | Артефакт |
|-------|------|----------|
| 1 | Выбор бизнес-задачи с понятным ROI | Business case |
| 2 | Аудит данных | Data quality report |
| 3 | Baseline-решение | Простой алгоритм + метрики |
| 4-5 | ML-модель | Прототип в Jupyter |
| 6 | Pre-production тест | Сравнение с baseline на holdout |
| 7-8 | Деплой и интеграция | Production API |
| 9 | A/B-тест в production | Решение о масштабировании |
| 10-12 | Масштабирование + мониторинг | MLOps pipeline |

Стандартный срок первого успешного ML-проекта — 9-12 месяцев. Дальше — быстрее благодаря наработанной инфраструктуре.
