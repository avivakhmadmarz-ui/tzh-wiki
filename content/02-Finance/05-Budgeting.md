# Бюджетирование

> Бюджетирование — это **процесс распределения ограниченных ресурсов** компании на конкретные действия. На уровне корпорации бюджет — это **финансовое выражение стратегии**: где компания решила играть, как побеждать, и сколько готова на это потратить. Эта заметка покрывает классический AOP (Annual Operating Plan — годовой операционный план), Rolling Forecast, Driver-Based Planning, ZBB (Zero-Based Budgeting), Beyond Budgeting и Variance Analysis.

## 1. AOP — Annual Operating Plan

### 1.1 Контекст и роль

**AOP (Annual Operating Plan — годовой операционный план)** — главный планировочный артефакт большинства компаний. Утверждается советом директоров (или собственником) на год вперёд и служит:
- **Целеполаганием** для всех функций (выручка, маржа, численность персонала — headcount, CAPEX)
- **Базой для KPI / бонусов** менеджмента
- **Контрактом** между функциями (продажи обещают, операции готовятся)
- **Финансовой базой** для всех инвестиционных решений в году

### 1.2 Цикл годового планирования

Типичный цикл AOP занимает **3-5 месяцев** (обычно сентябрь-декабрь для январского старта):

**Шаг 1 (август-сентябрь): обновление стратегии (strategy refresh).**
- Обновление стратегических предпосылок: где играем, как побеждаем
- Пересмотр OGSM / Hoshin Kanri / Strategy Map
- Принятие решений по новым продуктам / рынкам / экспансии

**Шаг 2 (сентябрь): цели сверху вниз (top-down targets).**
- CEO / CFO формулируют ключевые цифровые цели (рост выручки, EBITDA margin, ROIC)
- Каскадирование на дивизионы / регионы

**Шаг 3 (октябрь): планирование снизу вверх (bottom-up planning).**
- Каждое подразделение готовит свой план: выручка, затраты, численность, CAPEX
- Команда S&OP координирует предпосылки по спросу и поставкам (demand / supply assumptions)
- Финансы консолидируют

**Шаг 4 (ноябрь): согласование (reconciliation).**
- Сравнение итогов снизу вверх (bottom-up totals) с целями сверху вниз (top-down targets)
- Обычно появляется разрыв (gap) → переговоры по «как закрыть»
- Несколько итераций

**Шаг 5 (декабрь): финальное утверждение (final approval).**
- Совет директоров утверждает финальный AOP
- Каскадирование KPI на индивидуальные планы
- Бюджеты разблокированы для расходования

**Ключевой вывод 1.2.** AOP — это **не просто финансовый документ**. Это **политический процесс** в компании, где функции борются за ресурсы, защищают позиции, выторговывают «защищённые» цели. Качество AOP-процесса определяет, насколько год пройдёт по плану.

### 1.3 Структура AOP

Полный AOP содержит:
- **Прогноз P&L** по месяцам и продуктовым линиям / каналам
- **Прогноз Balance Sheet** — конечное состояние оборотного капитала, долга, собственного капитала (equity)
- **Прогноз Cash Flow** — OCF (Operating Cash Flow — операционный денежный поток), CAPEX, дивиденды
- **План капитальных затрат (capital expenditure plan)** — конкретные CAPEX-проекты с обоснованием (NPV / IRR)
- **План численности (headcount plan)** — найм, увольнения, ФОТ (фонд оплаты труда)
- **Каскад KPI (KPI cascade)** — конкретные цели для всех C-level (топ-менеджмента)
- **Реестр рисков (risk register)** — что может пойти не так и как митигируем

### 1.4 Проблемы традиционного AOP

Современная корпоративная критика AOP включает:

- **Дорогой процесс** — большие компании тратят 25 000+ человеко-часов на годовое бюджетирование (исследование Hackett Group)
- **Sandbagging** («песочные мешки») — менеджеры закладывают «подушки безопасности» в свои бюджеты, чтобы потом легко перевыполнить и получить бонус
- **Используется в нулевой сумме (zero-sum way)** — фокус на «защити свой бюджет», не на «оптимизируй портфель»
- **Антиинновационный уклон (anti-innovation bias)** — новые инициативы режутся, потому что они «не в плане»
- **Устаревает через 90 дней (outdated after 90 days)** — к Q2 предпосылки устарели, но план продолжает работать как «единая истина»

**Ключевой вывод 1.4.** Многие крупные компании (Statoil, Toyota, Handelsbanken) **отказались** от традиционного AOP в пользу подходов Rolling Forecast и Beyond Budgeting. Решение зависит от индустрии: для стабильных регулируемых — AOP работает; для турбулентных — нет.

## 2. Rolling Forecast — скользящий прогноз

### 2.1 Идея

**Rolling Forecast (скользящий прогноз)** — это **ежемесячный или ежеквартальный пересмотр** прогноза на следующие 12-18 месяцев, не привязанный к календарному году.

Логика:
- Каждый месяц добавляется ещё один период вперёд (rolling)
- Каждый месяц переоцениваются все предпосылки (assumptions)
- Прогноз остаётся «свежим» — не устаревает

### 2.2 Сравнение AOP vs Rolling Forecast

| Параметр | Традиционный AOP | Rolling Forecast |
|----------|------------------|------------------|
| Горизонт | Календарный год (январь-декабрь) | 12-18 месяцев вперёд от текущей даты |
| Частота (cadence) | 1 раз в год | Каждый месяц / квартал |
| Точность | Высокая в Q1, плохая к Q4 | Постоянно высокая |
| Стоимость процесса | Очень высокая (3-5 месяцев работы) | Средняя (несколько дней раз в месяц) |
| Бюджет менеджмента | Жёстко зафиксирован | Гибко адаптируется |
| KPI / бонусы | Привязаны к фиксированным целям | Требуют относительных измерений (relative measures — vs аналогов, vs рынка) |

### 2.3 Как внедрять Rolling Forecast

1. **Начать с пилота** на одном дивизионе / функции
2. **Driver-based подход** (планирование от драйверов, см. далее) — прогноз через драйверы, не через статьи (line-items)
3. **Сократить детализацию (reduce detail)** — не каждую строку, а топ-20-30 крупных категорий
4. **Автоматизировать** — Anaplan, Adaptive Insights, Workday Adaptive позволяют автоматизировать сбор и консолидацию
5. **Развязать с компенсацией (decouple from compensation)** — KPI должны быть на основе способности прогнозировать / адаптироваться, не «выполнил ли план»

### 2.4 Когда Rolling Forecast работает

- Динамичные индустрии (технологии, розница, fashion — модная индустрия)
- Компании с волатильным спросом
- Компании, переходящие на гибкие (agile) методологии управления
- При наличии современных BI-инструментов (Business Intelligence — бизнес-аналитика)

**Ключевой вывод 2.4.** Rolling Forecast — современная альтернатива AOP, особенно для **быстро меняющихся** индустрий. Главное препятствие — корпоративная политика: «как премию платить, если цели всё время меняются?». Решение — относительные измерения и оценка относительно рынка.

## 3. Driver-Based Planning — планирование через драйверы

### 3.1 Идея

**Driver-Based Planning** (планирование от драйверов) — построение финансовой модели не через статьи (line-items, например, «зарплата отдела маркетинга»), а через **причинно-следственные драйверы**:
- Revenue = количество клиентов × среднее число выручки на клиента
- Количество клиентов = маркетинговые расходы / CAC
- COGS = Revenue × отношение COGS к Revenue
- Стоимость персонала = FTE (Full-Time Equivalent — эквивалент полной занятости) × стоимость на FTE

Изменение **одного драйвера** автоматически пересчитывает всю модель.

### 3.2 Главные преимущества

- **Прозрачность** — видно, как изменения параметров влияют на финал
- **Анализ чувствительности (sensitivity analysis)** — легко делать сценарии «что если» (what-if)
- **Обоснование снизу вверх (bottom-up justification)** — каждое число имеет причину
- **Связь с операциями (connection to operations)** — драйверы привязаны к операционным метрикам (CAC, OEE — Overall Equipment Effectiveness — общая эффективность оборудования; OTIF — On Time In Full — поставка вовремя и в полном объёме), не к бухгалтерским категориям

### 3.3 Пример модели для e-commerce

```
Уровень 1 (драйверы спроса):
- Site Traffic = SEO_Visits + Paid_Visits + Direct_Visits
- Conversion Rate = baseline × seasonal_factor × promo_factor

Уровень 2 (revenue):
- Orders = Site Traffic × Conversion Rate
- Average Order Value = baseline × pricing_factor × mix_factor
- Revenue = Orders × AOV

Уровень 3 (costs):
- COGS = Revenue × (1 − Gross_Margin %)
- Marketing = CAC × New_Customers
- Logistics = Orders × Cost_per_Order

Уровень 4 (P&L):
- Gross Profit = Revenue − COGS
- EBITDA = Gross Profit − Marketing − Logistics − Fixed_OPEX
```

В таком модели изменение, например, Conversion Rate с 1.5% на 2% автоматически пересчитывает всё вниз до EBITDA.

**Ключевой вывод 3.3.** Driver-Based Planning — это **современная норма** для серьёзных финансовых моделей. Простые модели по статьям в таблицах (spreadsheet line-item) устарели; они не позволяют делать осмысленный анализ чувствительности.

### 3.4 Инструменты

- **Excel** с правильной структурой и Power Query / Power Pivot
- **Anaplan** — самая популярная корпоративная платформа для планирования от драйверов
- **Workday Adaptive Planning** — альтернатива Anaplan
- **Cube Software, Pigment, Vena** — современные SaaS-решения

## 4. ZBB — Zero-Based Budgeting

### 4.1 Идея

**ZBB (Zero-Based Budgeting — бюджет с нуля)** — методология, в которой каждый бюджет **начинается с нуля каждый год**, и каждая статья расходов должна быть **обоснована заново**. Противоположность инкрементальному бюджетированию (incremental budgeting — «в прошлом году было X, добавим 5% инфляции»).

История: разработан Питером Пирром в 1970-х, активно применялся в Texas Instruments, потом в правительстве США (администрация Картера). Возродился в 2010-х благодаря 3G Capital (AB InBev, Kraft Heinz).

### 4.2 Процесс ZBB

1. **Identify Decision Units** (выделение единиц принятия решений) — каждая активность / функция компании раскладывается на «пакеты решений» (decision packages — например, «маркетинг радио-рекламы в Q3»)
2. **Justify each from zero** (обоснование каждого с нуля) — для каждого пакета решений обосновать: зачем нужно, какая ROI, что произойдёт, если не финансировать
3. **Rank** (ранжирование) — ранжирование всех пакетов решений по ценности (value)
4. **Cut-off line** (линия отсечения) — провести линию через ранжированный список: «всё выше — финансируем, всё ниже — отказываемся»
5. **Document** (документирование) — каждое решение задокументировано

### 4.3 Главные результаты ZBB

3G Capital применила ZBB к Kraft Heinz после слияния 2015:
- Сократили SG&A (Selling, General and Administrative — коммерческие, общие и административные расходы) на 19% за 18 месяцев
- Закрыли 7 заводов
- Сократили 5 000+ позиций
- EBITDA margin вырос с 23% до 28%

Но долгосрочно ZBB критиковали:
- Недоинвестировали в маркетинг → бренды слабеют
- Недоинвестировали в инновации → продуктовый пайплайн истощился
- Акции Kraft Heinz упали 70% к 2019 году

**Ключевой вывод 4.3.** ZBB — мощный инструмент **сокращения затрат**, но опасен для долгосрочного создания ценности (value-creation). Применять в **стресс-ситуациях** (после поглощения, в антикризисном управлении), не как постоянную практику.

### 4.4 Когда ZBB работает / не работает

**Работает:**
- Постслияночная интеграция (post-M&A integration) с большими синергиями
- Антикризисные ситуации (turnaround situations)
- Зрелые бизнесы со слишком большим SG&A
- Когда нужно быстрое сокращение затрат

**Не работает:**
- Растущие компании (отвлекает менеджмент)
- R&D-интенсивные индустрии (режет инновации)
- Brand-driven (ориентированные на бренд) компании (режет маркетинг)
- Как постоянная практика (ROI методологии сам падает)

## 5. Beyond Budgeting — за пределами бюджетирования

### 5.1 Идея

**Beyond Budgeting** («за пределами бюджетирования») — радикальная альтернатива, отвергающая саму идею годового бюджетирования. Разработана Jeremy Hope и Robin Fraser, описана в одноимённой книге (2003).

Главный аргумент: **бюджет как обещание контракта вреден**. Создаёт «песочные мешки» (sandbagging), политические игры, культуру «защити свой пирог».

Альтернатива — **адаптивное управление (adaptive management)** через:
- **Непрерывное планирование (continuous planning)** — скользящий прогноз
- **Относительные цели (relative targets)** — KPI не «достичь $100 млн», а «обогнать аналогов на 5%»
- **Децентрализованное принятие решений (decentralized decision-making)** — каждое подразделение само принимает решения по расходам в рамках стратегии
- **Ресурсы по запросу (resource on demand)** — деньги выделяются под конкретные инициативы, не закреплены за подразделениями

### 5.2 Кейсы внедрения

**Handelsbanken** (шведский банк) — отказался от бюджетирования в 1972 году, использует Beyond Budgeting десятилетиями:
- Каждое отделение имеет полную автономию по решениям
- Сравнение с отделением-аналогом (peer) как главный ориентир
- Один из самых эффективных и устойчивых банков в Европе

**Statoil (Equinor)** — норвежская нефтяная компания — отказалась от бюджетов в 2005:
- Использует фреймворк Ambition to Action («от амбиций к действию»)
- Прогнозы пересматриваются каждый квартал
- KPI относительные (relative), а не абсолютные

### 5.3 12 принципов Beyond Budgeting

Принципы делятся на лидерские (6) и процессные (6):

**Лидерские принципы (Leadership Principles):**
1. **Purpose** (предназначение) — вовлекать людей через смысл, а не через цели
2. **Values** (ценности) — управляйте через ценности, а не через правила
3. **Transparency** (прозрачность) — открытая информация для саморегулирования
4. **Organization** (организация) — ткань малых автономных команд
5. **Autonomy** (автономия) — доверие людям в действиях
6. **Customers** (клиенты) — ориентация на клиента, не на иерархию

**Процессные принципы (Processes):**
7. **Rhythm** (ритм) — события по бизнес-ритму, не по календарю
8. **Targets** (цели) — относительные и устремлённые (aspirational)
9. **Plans and forecasts** (планы и прогнозы) — экономные (lean) и неискажённые
10. **Resource allocation** (распределение ресурсов) — по запросу (on-demand), а не годовой бюджет
11. **Performance evaluation** (оценка результатов) — многомерная
12. **Rewards** (вознаграждения) — общие (shared), не индивидуальные

**Ключевой вывод 5.3.** Beyond Budgeting — это **радикальная философия**, требующая полного пересмотра модели управления. Внедряется только при сильной приверженности CEO и долгосрочной инвестиции в культурную трансформацию.

## 6. Variance Analysis — анализ отклонений

### 6.1 Идея

После окончания периода (месяц, квартал) сравнивают **факт vs план** и анализируют **причины отклонений**. Это главная петля обратной связи (main feedback loop) бюджетирования.

### 6.2 Типы отклонений (для P&L)

**Отклонение по выручке (Revenue Variance):**
- **Volume Variance** (отклонение по объёму) — изменение из-за объёма продаж: (Actual_Volume − Budget_Volume) × Budget_Price
- **Price Variance** (отклонение по цене) — изменение из-за цены: (Actual_Price − Budget_Price) × Actual_Volume
- **Mix Variance** (отклонение по структуре) — изменение из-за структуры продаж (премиум vs базовая)
- **FX Variance** (валютное отклонение, Foreign Exchange) — изменение из-за валютных курсов

**Отклонение по затратам (Cost Variance):**
- **Material Price Variance** (отклонение по цене материала) — закупочная цена сырья
- **Material Quantity Variance** (отклонение по объёму материала) — потребление сырья на единицу
- **Labor Rate / Efficiency Variance** (отклонения по оплате труда / эффективности труда)
- **Overhead Variance** (отклонение по накладным расходам)

### 6.3 PVM-анализ (Price × Volume × Mix)

Стандартный способ декомпозиции изменения revenue:

```
ΔRevenue = Price Effect + Volume Effect + Mix Effect

Price Effect (эффект цены) = (P1 − P0) × V0      [рост цены на исходный объём]
Volume Effect (эффект объёма) = (V1 − V0) × P0   [рост объёма по исходной цене]
Mix Effect (эффект структуры) = (P1 − P0) × (V1 − V0) [двойной эффект]
```

**Пример:**
- Год 0: продали 100 ед × $10 = $1000
- Год 1: продали 110 ед × $11 = $1210
- ΔRevenue = $210

Декомпозиция:
- Эффект цены = ($11 − $10) × 100 = $100
- Эффект объёма = (110 − 100) × $10 = $100
- Эффект структуры = $1 × 10 = $10
- Итого = $210 ✓

**Ключевой вывод 6.3.** PVM-анализ — это **обязательная** компетенция категорийного менеджера / директора закупок. Без неё разговор «у нас выручка упала на 10%» бесполезен — пока не понятно, это цена (price), объём (volume) или структура (mix).

### 6.4 Цикл continuous improvement

```
1. Установить бюджет / forecast
2. Месяц закрывается
3. Variance analysis
4. Идентифицировать причины
5. Корректирующие действия / forecast update
6. Следующий месяц
```

**Ключевой вывод 6.4.** Variance analysis работает, только если есть **дисциплина закрытия** — ежемесячный variance review с конкретными action items. Без неё «отчёты по факту» становятся ретроспективной бумагой без влияния на бизнес.

## 7. Бюджетирование в современных условиях

### 7.1 Тренды (2020-2026)

- **Real-time financial planning** (финансовое планирование в реальном времени) — заменяет ежемесячные циклы
- **AI / ML в прогнозировании** — модели уже регулярно превосходят человеческие прогнозы
- **Децентрализованное распределение капитала (decentralized capital allocation)** — внутреннее венчурное финансирование (internal venture funding) для подразделений
- **ESG в бюджетировании** — отдельные строки на декарбонизацию, устойчивое развитие (sustainability)
- **Сценарное бюджетирование (scenario-based budgeting)** — несколько сценариев вместо одного «правильного»

### 7.2 Российский контекст

Особенности РФ-практики:
- Большинство компаний используют **гибрид AOP + Rolling Forecast** (квартальные пересмотры)
- Сильное влияние валютной волатильности → отдельные валютные сценарии (FX-scenarios) обязательны
- Регуляторные изменения требуют гибкости в бюджетировании
- Соответствие санкционным требованиям (sanctions compliance) — отдельная плоскость бюджетирования (анализ влияния — impact analysis — при новых пакетах санкций)
